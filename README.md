# ועד בית - מערכת ניהול עצמי לבניין מגורים

מערכת פשוטה, דו-לשונית עברית (RTL), לניהול ועד בית עצמאי: גבייה חודשית, הוצאות, משימות ותכנון תקציב שנתי.
כל החישובים (יתרות, גבייה, תחזיות) הם דטרמיניסטיים לחלוטין - קוד ונוסחאות בלבד, ללא AI.

## מבנה הפרויקט

```
├── client/     React (Vite) + Tailwind CSS, ממשק RTL
├── server/     Node.js + Express + Prisma (PostgreSQL)
└── render.yaml תבנית פריסה ל-Render
```

## הרצה מקומית

### דרישות מוקדמות
- Node.js 18+
- מסד נתונים PostgreSQL (מקומי או בענן, לדוגמה [Neon](https://neon.tech) / [Supabase](https://supabase.com) בחינם)

### שלבים

1. התקנת תלויות:
```bash
npm run install:all
```

2. הגדרת חיבור למסד הנתונים - העתיקו את הקובץ לדוגמה וערכו:
```bash
cp server/.env.example server/.env
```
ערכו את `server/.env` והזינו את כתובת ה-`DATABASE_URL` שלכם.

3. יצירת הטבלאות במסד הנתונים:
```bash
cd server && npx prisma db push && cd ..
```

4. טעינת נתוני דוגמה - יוצר משתמש-על (super admin) וגם בניין לדוגמה "נחל דליות 8" עם 14 דירות:
```bash
npm run seed
```
המשתמש-על נוצר עם האימייל `yohaivak86@gmail.com` והסיסמה מהמשתנה `SUPER_ADMIN_PASSWORD` (אם לא הוגדר, ברירת המחדל היא `changeme123` - מומלץ להחליף אותה בכניסה הראשונה).

5. הרצת השרת (טרמינל אחד) והלקוח (טרמינל שני):
```bash
npm run dev:server
```
```bash
npm run dev:client
```

האפליקציה תהיה זמינה בכתובת `http://localhost:5173` (הלקוח מתקשר עם השרת ב-`http://localhost:4000` דרך proxy).

## משתמשים והרשאות

המערכת תומכת בריבוי בניינים (multi-tenant) עם שלוש רמות הרשאה:
- **מנהל אתר (SUPER_ADMIN)** - המשתמש `yohaivak86@gmail.com` שנוצר על ידי הסקריפט `seed`. רואה ומנהל את **כל** הבניינים, ורק הוא יכול למנות מנהלי אתר נוספים.
- **נציג ועד** - לכל בניין בנפרד. רואה ומנהל כספים, דיירים, הוצאות, משימות ותקציב, ומאשר בקשות הצטרפות.
- **דייר** - רואה את הדף האישי שלו, ציר הזמן והמשימות; יכול לפתוח תקלה ("תקלת דייר") ולדווח על תשלום במזומן, אבל לא רואה כספים ולא דיירים אחרים.

### מסך הכניסה
יש שתי אפשרויות בלבד: **התחברות** ו**משתמש חדש**. אחרי יצירת המשתמש בוחרים: להצטרף לבניין קיים (לפי מספר הזמנה, או חיפוש לפי שם / כתובת / קוד - נציג הוועד מאשר), או לפתוח בניין חדש (בודד, או בתוך מתחם). בהתחברות יש הצגת סיסמה, ו"שכחתי סיסמה" שולח קישור איפוס במייל (דורש `RESEND_API_KEY`, ראו למטה).

### מתחמים
לכל מתחם מספר ייחודי שנוצר אוטומטית. אפשר לחפש מתחם לפי מספר, שם, כתובת או קוד. בקשת שיוך של בניין למתחם נשלחת למנהל המתחם (נציג ועד שפתח אותו) והוא מאשר או דוחה. אם אין מתחם מתאים, אפשר לפתוח חדש.

### כספים, משימות והוצאות צפויות
- **קו אדום לקופה** - ברירת מחדל 10,000 ₪, נקבע בלוח הבקרה. כשהיתרה הכוללת מתחת לקו, הכרטיס מסומן באדום.
- **הוצאות צפויות** - פריטים חודשיים, שנתיים וחד-פעמיים (ידנית או מקובץ Excel/CSV עם העמודות: שם, קטגוריה, תדירות, חודש, תאריך, סכום צפוי, הערות). הם מופיעים בלוח הבקרה כשהחודש מתקרב.
- **משימות** - אפשר לקשר משימה לפריט צפוי. עלות משימה עם מקור תשלום נרשמת אוטומטית גם כהוצאה (ושינוי באחד מעדכן את השני). עלות שדייר הזין בתקלה שפתח ממתינה לנציג הוועד, שבוחר מקור תשלום - רק אז היא נרשמת בקופה.

כל הנתונים (דיירים, הוצאות, משימות, תקציב) מבודדים לחלוטין בין בניינים - כל בקשת API מאומתת מול הרשאת המשתמש לאותו בניין ספציפי.

### הצבעות ומסמכים
- **הצבעות** - נציג ועד פותח הצבעה (2-8 אפשרויות, אפשר תאריך סגירה). **לכל דירה קול אחד**, גם אם גרים בה כמה דיירים (אפשר לשייך כמה חשבונות לאותה דירה ב"ניהול משתמשים"). לפני שינוי הצבעה קופצת שאלה "דייר X כבר הצביע Y - האם לעדכן?", והשינוי נרשם ביומן שרק הוועד רואה. כולם רואים תוצאות מצטברות בלבד, בלי לדעת מי הצביע.
- **פרוטוקולים ונהלים** - שתי לשוניות: "פרוטוקולים וסיכומי ועד" ו"נהלי בניין". הוועד מוסיף ועורך, כל הדיירים קוראים.
- **ציר זמן** (לשונית נפרדת, לכולם) - השנה כציר זמן אופקי: קו שעובר דרך 12 החודשים, סימון "היום", ומתחת לכל חודש ההוצאות הצפויות (חודשיות קבועות, שנתיות, חד-פעמיות ושורות התקציב) והמשימות עם תאריך; מה ששולם מסומן. "מצב תצוגה למסך" פותח אותו במסך מלא להצגה לדיירים (למשל בלובי), ובטלפון הוא מתהפך לציר אנכי. נציג ועד קובע אם הסכומים מוצגים גם לדיירים (ברירת מחדל: כן).
- **מסך ראשי** - כל מספר וכרטיס בו לחיץ ופותח את המסך המתאים. הציר מציג כברירת מחדל את החודש הנוכחי (עם חיצים בין חודשים), ו"השנה כולה" מוסיף תחזית הוצאות שנתית (מתוכנן מול שולם בפועל).
- בכל מסך יש כותרת בראשו וכפתור חזרה למסך הקודם (פועל גם עם כפתור החזרה של הדפדפן והטלפון).

### עיצוב
עיצוב צבעוני ומלא חיים: רקע כחלחל רך, כרטיסים לבנים מוגבהים, אריחי גרדיאנט (כחול, סגול, כתום, ירוק, ורוד), כפתורים תלת-ממדיים וסרגל צד כחול כהה. הוא בנוי כשכבה (`client/src/index.css`, בסוף הקובץ) מעל מבנה Lumen (`client/src/lumen.css`, ראו `DESIGN.md`). כל הצבעים והגרדיאנטים מוגדרים כמשתנים ב-`lumen.css`, כך שאפשר להחליף צבע במקום אחד. העיצוב בהיר בלבד (אין מצב כהה).

## פריסה ל-Render

הפרויקט כולל קובץ `render.yaml` (Render Blueprint) המגדיר אוטומטית:
- Web Service אחד (Node) שבונה את הלקוח והשרת ומגיש את שניהם יחד.
- מסד נתונים PostgreSQL בתוכנית החינמית.

### שלבים
1. דחפו את הקוד ל-GitHub (ראו למעלה).
2. ב-[Render Dashboard](https://dashboard.render.com), בחרו **New > Blueprint**.
3. חברו את ה-repository - Render יזהה את `render.yaml` אוטומטית וייצור את שני השירותים (Web Service + PostgreSQL).
4. אשרו את הפריסה. Render יריץ אוטומטית:
   - `npm run build` - מתקין תלויות, בונה את הלקוח (`client/dist`) ומריץ `prisma generate`.
   - `npm start` - מריץ `prisma migrate deploy` (יוצר את הטבלאות במסד הנתונים בענן) ואז מפעיל את השרת.
5. לאחר הפריסה הראשונה, ב-Render Dashboard הגדירו את משתנה הסביבה `SUPER_ADMIN_PASSWORD` בשירות (הוא מסומן `sync: false` בכוונה, כדי שלא ייחשף בקוד), ואז פתחו **Shell** בשירות והריצו פעם אחת:
```bash
npm run seed --prefix server
```
זה יוצר את חשבון מנהל-העל (`yohaivak86@gmail.com`) ואת בניין הדוגמה. לחלופין, אפשר לוותר על הזרעת נתוני הדוגמה ופשוט להירשם דרך מסך "בניין חדש" באפליקציה - זה יוצר בניין וחשבון אדמין אמיתיים מההתחלה.

### משתני סביבה
רוב המשתנים מוגדרים אוטומטית על ידי `render.yaml`:
- `DATABASE_URL` - כתובת החיבור ל-Supabase (Session pooler). מוגדר ידנית ב-Dashboard של Render (`sync: false`), ולא נוצר אוטומטית.
- `PORT` - פורט ההאזנה של השרת.
- `NODE_ENV=production`
- `JWT_SECRET` - נוצר אוטומטית (`generateValue: true`) לחתימת הסשן.
- `SUPER_ADMIN_PASSWORD` - יש להגדיר ידנית ב-Dashboard לפני הרצת `npm run seed` (משמש רק ליצירת חשבון מנהל-העל).

משתנים אופציונליים (ללא אף אחד מהם האפליקציה עובדת, אבל לא יישלחו מיילים):
- `RESEND_API_KEY` - מפתח של [Resend](https://resend.com) לשליחת מיילים: איפוס סיסמה, הצעות לשיפור ובקשות הצטרפות למתחם.
- `EMAIL_FROM` - כתובת השולח. ברירת המחדל `onboarding@resend.dev` מאפשרת שליחה רק לבעל חשבון ה-Resend; לשליחה לכולם צריך לאמת דומיין משלכם ב-Resend.
- `APP_URL` - הכתובת הציבורית של האתר (למשל `https://vaad-bayit.onrender.com`), משמשת בקישור האיפוס שנשלח במייל. אם לא מוגדר, נלקחת הכתובת של הבקשה.

## עקרונות מרכזיים

- **דטרמיניזם מלא**: כל יתרה, חוב וגירעון מחושבים בזמן אמת מתוך רשומות בפועל (יתרת פתיחה + תשלומים מאושרים - הוצאות), ללא ניחוש או מודלים חיצוניים.
- **שני ארנקים נפרדים**: הבניין מנהל בו-זמנית קופת בנק/PayBox וקופת מזומן, כאשר כל תנועה משויכת במפורש לאחת מהן. הסכום הכולל הוא תמיד סכום שתי הקופות.
- **אישור תשלומי מזומן**: כאשר דייר מדווח על תשלום במזומן, הסכום *אינו* נכנס לקופה עד לאישור ידני של הוועד ("אישור תשלום דייר") - כדי למנוע רישום כפול או שגוי.
